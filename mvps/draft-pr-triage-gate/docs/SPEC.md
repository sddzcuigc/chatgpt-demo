# 产品规格

- 使用者：独立开发者、Agent 工作流负责人、小型产品团队
- 决策者：项目负责人、维护负责人
- 付款者：内部工具团队、咨询交付团队
- 不解决的损失：草稿 PR 堆积、主题重复、评审上下文膨胀、主分支长期没有可用增量
- 现有替代：GitHub Projects、人工周会、WIP 看板
- 通用 AI 可替代性：AI 可总结 PR，但不能替团队承担关闭、合并和放弃的责任
- 商业模式：团队流程模板、GitHub App、咨询交付门禁
- 维护成本：低；核心是规则与 GitHub 数据适配
- 合规/IP：只读取仓库元数据时风险低；不得泄露私有代码和评论
- 壁垒：PR 老化、重复主题与最终采用结果之间的长期数据
